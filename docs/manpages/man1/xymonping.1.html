NAME

xymonping - Xymon ping tool

 

SYNOPSIS

xymonping [--retries=N] [--timeout=N] [--samples=N [--per-host-interval=MS]] [IP-addresses]

 

DESCRIPTION

xymonping(1) is used for ping testing of the hosts monitored by the xymon(7) monitoring system. It reads a list of IP addresses from stdin, and performs a "ping" check to see if these hosts are alive. It is normally invoked by the xymonnet(1) utility, which performs all of the Xymon network tests.

Optionally, if a list of IP-addresses is passed as command-line arguments, it will ping those IP's instead of reading them from stdin.

xymonping only handles IP-addresses, not hostnames: IPv4, or IPv6 with a link-local address given as addr%interface. At most 65535 addresses are pinged in one run; the rest are refused with an error.

xymonping was inspired by the fping(1) tool, but has been written from scratch to implement a fast ping tester without much of the overhead found in other such utilities. The output from xymonping is similar to that of "fping -Ae".

xymonping probes multiple systems in parallel, sending at most --max-pps packets per second, so a run takes about the number of hosts divided by that rate, plus the time the slowest host takes to answer or to be given up on (about 4 seconds with the default options).

 

PRIVILEGES

xymonping needs to send and receive ICMP Echo (ping) packets. It first tries an unprivileged ICMP socket (SOCK_DGRAM). Linux allows one to a user whose group is inside the net.ipv4.ping_group_range sysctl; many distributions set that range to cover every group. To allow it everywhere:

   sysctl -w net.ipv4.ping_group_range="0 2147483647"

If that socket is refused, xymonping falls back to a raw socket, which needs root: install xymonping suid-root. It drops root privileges immediately, and only regains them to open the raw socket; no user-supplied or network data is handled while privileged.

File capabilities work as well: setcap cap_net_raw+ep on the binary lets xymonping open the raw socket without being suid-root.

IPv6 addresses need the unprivileged ICMPv6 socket or root in the same way.

 

OPTIONS

--retries=N
Sets the number of retries for hosts that fail to respond to the initial ping, i.e. the number of ping probes sent in addition to the initial probe. The default is --retries=3, as with fping, to ping a host 4 times before concluding that it is not responding.

--timeout=N
Determines the timeout (in seconds) for the first ping to a host; each retry waits 1.5 times longer than the one before, as fping's -t and -B do. A reply that arrives later than its own ping's timeout does not count. Without this option the first ping waits 500 ms, so a host that never answers is given up on after about 4 seconds (500, 750, 1125 and 1688 ms), and one whose replies take longer than that is reported unreachable: --timeout=5 gives such a link back the old 5 seconds a try. With --samples every ping gets the same timeout: by default the --per-host-interval, at most 2 seconds, as in fping's count mode.

--responses=N
xymonping normally stops pinging a host after receiving a single response, and uses that to determine the round-trip time. If the first response takes longer to arrive - e.g. because of additional network overhead when first determining the route to the target host - it may skew the round-trip-time reports. You can then use this option to require N responses, and xymonping will calculate the round-trip time as the average of all of responsetimes.

--samples=N
Enables SmokePing-style probing: sends exactly N pings to each host (N at most 1000), without retries, and records every round-trip time rather than only the average. The pings to one host are spaced by --per-host-interval, so each host gets one train of N pings per run. The output line for each host gains fields after the usual text, so that existing parsers keep working: an alive host gets the samples and the loss, an unreachable one the loss alone: 

  1.2.3.4 is alive (311 usec) samples=0.000310,0.000320,0.000305 loss=0/3
  1.2.3.5 is unreachable loss=3/3
Samples are in seconds; loss is reported as lost/total. A ping counts as lost when no reply arrives within --timeout of sending it. Without this option (or with N=0) the output is unchanged. xymonnet(1) runs xymonping this way for hosts carrying the "smoke" tag in hosts.cfg(5).
--per-host-interval=MS
With --samples, the time in milliseconds between two pings to the same host. The default is 1000, as with fping's -p option and SmokePing: the N pings form a train of (N-1) seconds. Pings to different hosts are interleaved within that spacing, and no two pings leave closer together than --max-pps allows.
--max-pps=N
Maximum number of packets per second. This limits the number of ICMP packets xymonping will send per second, by enforcing a brief delay after each packet is sent. The default setting is to send a maximum of 100 packets per second, fping's default. Note that increasing this may cause flooding of the network, and since ICMP packets can be discarded by routers and other network equipment, this can cause erratic behaviour with hosts recorded as not responding when they are in fact OK.

--source=ADDRESS
Use ADDRESS as the source IP address of the ping packets sent. On multi-homed systems, allows you to select the source IP of the hosts going out, which might be necessary for ping to work.

-iMS, -rN, -tMS, -SADDRESS
The fping options xymonping accepts, meaning what they mean to fping: the least time in milliseconds between two pings, the retries, the first ping's timeout in milliseconds, and the source address. Any other option starting with - is ignored.

--debug
Enable debug output. This prints out all packets sent and received.
